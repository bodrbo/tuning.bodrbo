# Интеграция формы с «Бодрым Бизнесом»

Форма на `tuning.bodrbo.ru` отправляет заявку на локальный PHP-обработчик. Он проверяет поля, ограничивает частоту запросов и передаёт данные в «Бодрый Бизнес» по защищённому server-to-server API.

```text
браузер → tuning.bodrbo.ru/submit-request.php → business.bodrbo.ru/api/integrations/tuning-leads
```

Секрет API никогда не передаётся браузеру и не хранится в Git.

## 1. Создать общий секрет

В SSH-терминале Beget выполните:

```bash
openssl rand -hex 32
```

Сохраните результат в менеджере паролей. Один и тот же секрет нужно добавить в обе серверные конфигурации ниже.

## 2. Настроить «Бодрый Бизнес»

В файле `.env`, который загружает Passenger приложения `business.bodrbo.ru`, добавьте:

```dotenv
TUNING_SITE_WEBHOOK_SECRET=ВСТАВЬТЕ_СЕКРЕТ
```

Файл `.env` находится рядом с рабочим `passenger_wsgi.py` и не должен попадать в Git. После изменения перезапустите приложение через панель Beget или Passenger.

## 3. Настроить сайт тюнинг-центра

После обновления репозитория сайта создайте конфигурацию за пределами `public_html`:

```bash
cd ~/tuning.bodrbo.ru
cp public_html/integration-config.example.php integration-config.php
chmod 600 integration-config.php
nano integration-config.php
```

Укажите тот же секрет:

```php
<?php
return [
    'endpoint' => 'https://business.bodrbo.ru/api/integrations/tuning-leads',
    'secret' => 'ВСТАВЬТЕ_СЕКРЕТ',
];
```

Итоговый путь должен быть таким:

```text
~/tuning.bodrbo.ru/integration-config.php
```

Не переносите этот файл в `public_html` и не добавляйте его в Git.

## 4. Проверить

1. Откройте форму на `https://tuning.bodrbo.ru/`.
2. Отправьте тестовую заявку с узнаваемым именем.
3. Убедитесь, что форма показала сообщение об успешной отправке.
4. Откройте «Бодрый Бизнес» → **Тюнинг-центр → Заказы**.
5. Должен появиться заказ со статусом **Новая заявка** и источником `tuning_site`.
6. Повторная доставка с тем же `request_id` не должна создавать дубликат.

## Что сохраняется в заказе

- имя и телефон клиента;
- модель катера, если указана;
- описание задачи;
- адрес страницы, с которой отправлена форма;
- время отправки;
- уникальный идентификатор для защиты от дублей.

Для каждой заявки корпоративная система также создаёт связанный финансовый проект.

## Диагностика

- `422` — посетитель ввёл некорректные данные;
- `429` — превышено пять попыток за десять минут с одного IP;
- `502` — корпоративная система не ответила или вернула ошибку;
- `503` — отсутствует `integration-config.php`, секрет или PHP cURL.

Серверные ошибки записываются без имени, телефона и текста заявки. В журнал попадают только технический статус и `request_id`.
